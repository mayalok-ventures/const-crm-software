## 3. Asynchronous Queue, Retry & Dead-Letter Pipeline

All high-throughput external webhooks adhere to a non-blocking asynchronous architectural pattern:

1. **Fast Ingress & Signature Gate**: The endpoint verifies the signature within $\le 5\text{ms}$ and responds with HTTP 200/202 to avoid provider timeout disconnects.
2. **Deduplication Filter**: The event is persisted to the `WebhookEvent` MongoDB collection. A partial unique compound index `{ provider: 1, externalLeadId: 1 }` with `{ status: { $ne: 'failed' } }` atomically suppresses duplicate deliveries.
3. **Tenant Routing**: The worker resolves the destination `workspaceId` and `companyId`. If unmapped, the payload is safely parked in a quarantine log for SuperAdmin audit.
4. **Exponential Backoff**: If downstream lead creation fails (e.g. database lock, validation error), the queue service retries the event with exponential backoff:
   $$\text{Delay} = 2^n \times 1\text{ second} \quad (\text{where } n \in [1, 5])$$
5. **Dead-Letter Queue (DLQ)**: Upon the 5th consecutive failure:
   - The event transitions to `status: 'dead_letter'`.
   - A critical incident alert is posted to `/api/superadmin/error-logs`.
   - A workspace `Notification` is dispatched to the tenant owner.
6. **SuperAdmin Re-drive Engine**: The SuperAdmin command center provides an atomic re-drive action (`POST /api/integrations/events/:id/retry`) allowing failed events to be re-evaluated after configuration repairs.

## 5. Security Architecture & Boundary Separation

### 5.1. The Critical Distinction: Tenant Admin vs Platform SuperAdmin
A critical root cause of past confusion was the accidental mixing of two distinct administrative scopes:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        SAHYAK CRM ARCHITECTURE                         │
├───────────────────────────────────┬────────────────────────────────────┤
│      TENANT WORKSPACE ADMIN       │        PLATFORM SUPER ADMIN        │
│          (/api/admin/*)           │       (/api/superadmin/*)          │
├───────────────────────────────────┼────────────────────────────────────┤
│ • Scope: Single College / Agency  │ • Scope: Entire SaaS Cloud Fleet   │
│ • Roles: counselor, manager, admin│ • Roles: STRICTLY superadmin ONLY  │
│ • Manages:                        │ • Manages:                         │
│   - Candidate Leads               │   - Tenant Organizations           │
│   - Follow-up Schedulers          │   - Global User Directory          │
│   - Staff Hierarchy               │   - SaaS Pricing Plans & MRR       │
│   - Pipeline Stages               │   - Fleet-wide Webhook Telemetry   │
│   - WhatsApp Message Templates    │   - Database Health & CPU Load     │
│   - Lead Distribution Rules       │   - Emergency Broadcast Alerts     │
│ • Security Boundary:              │ • Security Boundary:               │
│   Tenant-isolated (workspaceId)   │   Global Platform Operator Key     │
└───────────────────────────────────┴────────────────────────────────────┘
```

### 5.2. Hardened Access Control Rules
1. **Zero Tenant Access to Platform Code**: Tenant admins (`role: 'admin'`) and owners (`companyRole: 'owner'`) are permanently blocked from `/api/superadmin/*` with HTTP 403 Forbidden.
2. **Deterministic Root Identity**: The sole default superadmin identity is configured as:
   - **Email / Username**: `superadmin@sahyak.com`
   - **Password**: `Kunalxca2026@`
   - **Role**: `superadmin`
   - **Flag**: `isAdmin: true`
3. **Impersonation Lockdown**:
   - SuperAdmin accounts can NEVER be impersonated.
   - Any token issued with `supportMode: true` is permanently barred from accessing `/api/superadmin/*`.
4. **Rate Limiting**:
   - `superAdminLimiter` strictly bounds platform administrative mutation routes (120 req / 15 min per user).
   - Ingress endpoints are protected by IP-based brute-force abuse protection.
